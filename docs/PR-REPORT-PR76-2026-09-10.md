## 一、核心特性

### 1. 事件汇报概率门（report_gates）— `pet/report_gates.py`（新增）

将所有联动气泡的开关控制统一为**概率门**模型：

| 门名 | 默认概率 | 说明 |
|------|---------|------|
| `state` | 1.0 | 开始干活 / 思考 |
| `activity` | 0.6 | 过程汇报（读文件/跑命令/改代码…） |
| `approval` | 1.0 | 审批与提问 |
| `done` | 1.0 | 任务完成 |
| `exec_failed` | 1.0 | 失败与错误 |
| `model_access` | 1.0 | 模型访问失败 |
| `stuck` | 1.0 | 卡住 / 行为重复 / 循环检测 |
| `bridge` | 1.0 | 桥接安装与写回 |

- **0.00** = 该类完全不汇报；**1.00** = 全部汇报；中间值按概率抽稀
- 概率只作用于「出气泡」这一步，检测器本身与 `raw_record` 数据链路不受影响
- 旧布尔开关（`notify_state` / `notify_done` / `notify_activity`）自动迁移为 1.0/0.0
- 旧百分比 `report_probability`（0-100）自动迁移为 activity 概率（0-1）

**涉及文件**:
- `pet/report_gates.py` — 纯数据与纯函数，门名/默认值/事件→门映射/清洗/判决
- `pet/agent_link.py` — `_report_allowed()` 概率门判决入口；各汇报路径（开始干活/过程/审批/完成/失败/卡住/循环）接入概率门
- `pet/config.py` — 默认值迁移、`_clean_agent_link_data` 清洗
- `pet/context_menus/shared.py` — 右键菜单改为 0/1 两端快捷入口
- `pet/settings_widgets.py` — 新增 `ProbabilitySlider`（0.00-1.00 滑块）和 `CollapsibleGroup`（可折叠分组容器）
- `pet/modern_settings_dialog.py` — 设置页「事件气泡触发概率」可折叠框，按事件聚合类别分组

## 二、Bug 修复

### 1. 菜单布局编辑器 QTimer 崩溃（`pet/settings_menu_layout_editor.py`）
- **问题**: `QTimer.singleShot(0, ...)` 静态调用无法取消、不随编辑器销毁；窗口关闭后回调触发 `RuntimeError: Internal C++ object already deleted`
- **修法**: 改为成员 timer（随编辑器销毁）+ `shiboken6.isValid()` 有效性闸门

### 2. 全量测试 access violation（`tests/conftest.py`）
- **问题**: 全局 `processEvents()` 冲刷其他测试遗留的排队事件，在已销毁/已删除的原生对象上触发 `0xC0000005`
- **修法**: 逐对象定向派发 `DeferredDelete`，不调用共享 `QApplication.processEvents()`

### 3. 桥接硬失败误报（`integrations/dsh-pet-bridge`）
- **问题**: `execution/failed` 的硬失败判定逻辑有缺陷，恢复后未清零
- **修法**: 改为读 `reason` 且恢复即清零

### 4. 模型访问失败连续计数丢失（`pet/agent_event_normalizer.py`）
- **问题**: 归一化后事件缺少上游事件名（`event` 字段为空），`ModelAccessTracker._resets` 无法正确识别 `agent/status` 复位信号，导致连续模型访问失败的 streak 计数在不该复位时被清零、或在该复位时未清零
- **修法**: 新增 `_EVENT_ALIASES`（`AgentStatus` → `agent/status`）别名表；归一化时填充 `event` 字段为规范名，确保消费端词表匹配一致

### 5. 连续点击桌宠动画不从头播放（本次 session 修复）
- **问题**: `_switch` 中 `stop()` 若触发圈末软停驻留（`_soft_parked=True`），`start()` 走续圈路径直接返回，不重置 `_queue`/`_frame_index`，动画从圈边界继续而非帧 0
- **修法**: `_switch`/`_switch_fallback` 中 `stop()` 之后、`jumpToFrame(0)` 之前强制 `movie._soft_parked = False`
- **涉及文件**: `pet/window.py`（+6 行）

## 六、已知风险与后续

1. **`catalog.py` 移除 `names_ordered` 保序**：set 迭代序随 `PYTHONHASHSEED` 随机化，可能影响低优预热池顺序和关键词兜底匹配。本次未纳入修复范围，需单独评估是否回滚。
2. **`_soft_parked` 强制清除**：修复了动画不从头播放的问题，但会跳过 batch8 续圈优化——连续点击同一动画时每圈都会重启 ffmpeg 进程。对使用体验影响可接受（点击动画通常非循环），但高频循环动画（idle）的续圈优化不受影响（idle 走 `_switch` 切到 click 时清除的是 click 的 `_soft_parked`，不影响 idle 自身的续圈）。
3. **概率门默认值变更**：`stuck_detect` / `pattern_detect` 默认从 False 改为 True，新用户首次使用会启用卡住检测和行为模式检测。需确认是否符合产品预期。
